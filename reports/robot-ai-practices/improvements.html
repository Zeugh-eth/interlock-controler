arm-daemon · practices review · 23 October 2026

Five of the report's ten practices are already in place. The next three are about evidence, not perception.

The practices report recommends a belief store, object identities and a learned policy. Tonight's runs say the cheaper problems come first: grasp and place outcomes are still declared from a gripper percentage, the camera-to-table projection is 5 cm off, and the demo cards cannot tell a real pick from a miss. Fix those three, and the belief store becomes a data problem instead of a guess.

Take now (this week, in the skills layer)

1. Verify "held" and "placed" by evidence, not by gripper percent

The report's rule: after closing, do not declare held because the command completed; lift a little and check. Tonight shows why both heuristics in use are wrong.

  • The fork's successful pick at 04:17 closed to 1.5 % and lifted at 0.9 %, below both EMPTY_PCT = 3.0 in skills.py and the 2.5 % cut in demolib. The carton was held at the fingertips and later placed. Both layers would have called it a miss.
  • My 03:51 miss closed to 1.0 % and knocked the carton over. Same reading, opposite reality.

Change: grasp() lifts 2 cm, then compares two things: the fingertip region of the annotated frame before and after the lift (object pixels move with the jaws or stay on the table), and the gripper load. Return held, empty or uncertain; never a bare success. release() retreats and re-observes the drop point before reporting placed. The demo card uses the same verdict instead of the percent threshold.

Cost: about 2 hours. Removes the single biggest false-claim path in the agent loop.

2. Calibrate the projection against the jaws, in cm, at two heights

project() landed the pad and the carton about 5 cm off in both fork runs, the same parallax bias each time. The report asks for a verified camera-to-gripper transform with error measured across the working area.

Change: a 10-minute routine: place a marker, drive the jaw target onto it at 8 cm and 4 cm tool height, record pixel and tool xyz, fit the fingertip offset per height. Store it in lab/arm-vision/gripper-camera-cal.json with a version string, and write that version into every demo row (the report's "calibration version with each observation").

Cost: 1 hour of code plus 10 minutes at the arm. Turns three correction moves per approach into one.

3. Make contact detection work on light objects, and make descent the default

descend_to_contact() never fired at 350 load units while a carton touched a pad. My miss came from trusting a model height instead of descending to contact. The report: keep stopping local and bound motion in one place.

Change: contact = lag check (commanded minus measured on shoulder_lift and elbow_flex) with a 2° threshold at 0.5 cm steps, plus a load rise relative to the previous step rather than an absolute number. Back off 1 cm after contact, then grasp. Record the contact height in the demo card as contact_z_cm so the next run can start lower.

Cost: 1 hour. Tested against the fake backend with a sag mode, which already exists in the test suite.

Take next (after the three above hold up on five picks)

4. Object records in the base frame, with last-seen and visibility

The report's minimum record: id, label hypotheses, pose in base, uncertainty, last seen, visibility, relations, evidence. The vision worker already projects detections onto the table grid in cm. The missing piece is persistence: today a detection dies with the frame.

Change: a small beliefs.py in the skills layer: each annotated frame updates records keyed by label plus position (within 4 cm = same object), stores pose_base_cm, last_seen, visibility (visible, outside view, held, lost) and the frame name as evidence. No merging across similar labels; two cartons stay two records until the agent inspects. Expose GET /beliefs and an MCP objects() tool. When grasp() returns held, the record's pose follows the tool transform; after release it is re-observed, not carried.

Cost: half a day. Only worth it once item 1 produces trustworthy held/placed transitions to feed it.

5. Fix the demo cards for episodes that start held, and add the report's replay tests

The place demo at 04:38 is labelled never_closed because the summariser assumes a pick shape. Episodes that start with the gripper closed on an object need a place shape: carry, descend, release, retreat.

Change: detect the initial state (gripper between 3 and 20 % and a lift in the first seconds = held) and pick the template. Then build the report's six scenarios as recorded-sequence tests on the demos directory: hidden object, camera move, two similar objects, closes on air, slip during carry, stale frame. Four of the six already have real recordings from tonight.

6. Stamp every observation with age and pose, and refuse stale ones everywhere

observe() already rejects frames older than 0.5 s. The daemon's /state carries t, and the annotated view carries the joints it was drawn with. Two gaps: demo rows do not say how old the frame was when the row was written, and look() in the MCP does not refuse a stale frame, it only reports the age.

Change: add frame_age_s and cal_version to each demo row; make look() return stale: true with the age and tell the model not to act on it. Ten lines.

Skip for now, with the reason

  • Grounded SAM 2 / ConceptGraphs / FoundationPose. The failures tonight were not recognition failures; YOLO-World found the carton and the pad every time. Identity persistence (item 4) can be built on the current detector first.
  • A learned policy (LeRobot, OpenPI, LingBot-VA). Seven episodes, three of them failures. The report itself says to collect reliable demonstrations first. The teleop-through-daemon path and the cards are the collection pipeline; revisit at 30 clean episodes.
  • MoveIt 2 / ROS. The daemon already is the single motion authority with clamp, load/lag freeze and a table check. A ROS migration buys nothing until there is a scene model to collide against.
  • Bounded video queues and async inference. There is no inference queue: the agent polls one frame per decision. Not a problem yet.

Method and caveats

Statuses come from reading skills.py, demolib.py, vision_worker.py and the seven demo cards, plus the two fork sessions' own run notes (pick 04:17, place 04:38, vision fixes). No arm was moved for this study. "Done" means the behaviour is enforced in code and was exercised tonight, not that it is tested against the report's thresholds. The 5 cm projection bias is the forks' measurement, not re-measured here. Costs are my estimates for one person at the arm.
